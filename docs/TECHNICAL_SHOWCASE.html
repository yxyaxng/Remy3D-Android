原理 P1：空间采样算法体系（体素哈希、泊松盘与梯度分箱）

对应源码：PhotoReconstructor.kt SurfaceMesher.kt UniversalPlyLoader.kt
Sampling Theory
📌 原理概述
采样层采用三级策略：前端基于 Sobel 梯度执行 2,500 边缘点 + 3,500 表面点的分箱采样，兼顾几何边界与内部连续色彩；中端通过三维体素空间哈希合并重复点并滤除离群噪点；后端在加载外部大型 PLY 模型时采用自适应步长流式采样，将显存顶点数量控制在移动端安全阈值内。

1. 梯度显著性与分箱配额采样 (Gradient Binning)

利用二维 Sobel 算子计算图像亮度梯度幅值 $M(x,y) = \sqrt{G_x^2 + G_y^2}$，平衡边缘特征与内部表面采样：

// PhotoReconstructor.extractFeatures 分箱配额 val edgeFeatures = features.filter { it.strength > 0.35f } val surfaceFeatures = features.filter { it.strength <= 0.35f } // 刚性轮廓配额 2,500 点 + 内部表面均匀填充 3,500 点 val selectedEdges = edgeFeatures.sortedByDescending { it.strength }.take(2500) val selectedSurfaces = surfaceFeatures.shuffled().take(6000 - selectedEdges.size)

2. 体素网格空间哈希下采样 (Voxel Grid Hashing)

将连续空间 $\mathbb{R}^3$ 划分为边长 $v_{\text{size}} = 0.045\text{m}$ 的体素立方体，通过大素数异或哈希或 64 位移位键实现 $O(1)$ 聚类降噪：

// 离散体素坐标映射与质心聚合 i = floor(x / v_size), j = floor(y / v_size), k = floor(z / v_size) H(i,j,k) = (i * 73856093) ^ (j * 19349663) ^ (k * 83492791) // 同体素内所有采样点求几何质心与色彩均值，滤除孤立噪点

3. 泊松盘均匀表面约束 (Poisson Disk)

在生成单体模型表面高斯椭球时，约束任意两椭球中心欧氏距离 $\|p_i - p_j\|_2 \ge r_{\min}$，符合蓝噪声频谱分布，避免椭球过密导致的深度闪烁或过疏导致的表面缝隙。

4. 自适应步长流式采样 (Adaptive Stride)

解析外部百万级 PLY 文件时，按安全上限 $N_{\max} = 50,000$ 动态计算步长 $\text{stride} = \lceil N / N_{\max} \rceil$，边读取字节流边抽样，内存峰值恒定低于 $160\text{MB}$。

原理 P2：3D 高斯椭球参数化与 EWA 屏幕各向异性投影

对应源码：UniversalPlyLoader.kt GaussianRenderer.kt
3DGS Math
📌 原理概述
3DGS 的基本几何图元是具有三维尺度矩阵 $S$ 与四元数旋转矩阵 $R$ 的各向异性三维高斯椭球。渲染时基于 Zwicker EWA 算法将三维协方差矩阵投影至二维屏幕平面，在顶点着色器中沿椭球主轴方向拉伸椭圆面片以拟合物体连续表面。

1. 三维协方差矩阵的正定分解

三维高斯核定义为 $G(x) = \exp\left(-\frac{1}{2}(x-\mu)^T \Sigma^{-1} (x-\mu)\right)$。为保证协方差矩阵 $\Sigma$ 半正定，将其分解为旋转矩阵 $R$（由单位四元数 $q=(w,x,y,z)$ 构造）与对角尺度矩阵 $S = \text{diag}(s_x, s_y, s_z)$：

Σ = R · S · ST · RT // PLY 文件中 scale 以对数存储，加载时通过指数还原物理尺寸： scaleX = exp(raw_scale_0) scaleY = exp(raw_scale_1) scaleZ = exp(raw_scale_2)

2. EWA Splatting 与球谐函数 (SH) 颜色采样

给定视图变换 $W$ 与透视投影雅可比矩阵 $J$，屏幕二维投影协方差为 $\Sigma' = J W \Sigma W^T J^T$。零阶球谐基系数（`f_dc_0..2`）通过球面常数基 $Y_0^0 = \frac{1}{2\sqrt{\pi}} \approx 0.282095$ 还原漫反射基底色：

// UniversalPlyLoader.kt 球谐零阶颜色解码 val SH_C0 = 0.28209479f val r = (0.5f + SH_C0 * f_dc_0).coerceIn(0f, 1f) val g = (0.5f + SH_C0 * f_dc_1).coerceIn(0f, 1f) val b = (0.5f + SH_C0 * f_dc_2).coerceIn(0f, 1f)

原理 P3：体积辐射度混合、逆 Sigmoid 解码与屏幕 Gamma 校正

对应源码：GaussianRenderer.kt (FS) UniversalPlyLoader.kt
Shader Physics
📌 原理概述
标准 3DGS PLY 文件中的 `opacity` 存储为逆 Sigmoid (Logit) 空间浮点数，加载时需执行标准 Sigmoid 激活还原；同时球谐函数计算出的颜色位于物理线性光度空间，片元着色器中通过 Gamma 1.85 转换与 1.28 倍饱和度补偿适配移动端 sRGB 屏幕。

1. 不透明度逆 Sigmoid (Logit) 激活还原

3DGS 训练时将 $\alpha \in (0,1)$ 存储为 $\text{logit}(\alpha) = \ln\frac{\alpha}{1-\alpha}$。解析时执行 Sigmoid 还原：

// UniversalPlyLoader.kt α = 1.0f / (1.0f + exp(-raw_opacity))

2. 片元着色器 Gamma 空间转换与中心强化

将物理线性辐射亮度转换为屏幕 sRGB 空间，并通过 `smoothstep` 强化高斯中心不透明度：

// GaussianRenderer.kt 片元着色器 (FS) float gaussian = exp(-2.2 * dot(vUV, vUV)); float finalAlpha = clamp(vAlpha * gaussian, 0.0, 1.0); float gray = dot(vColor, vec3(0.299, 0.587, 0.114)); vec3 col = mix(vec3(gray), vColor, 1.28); // 饱和度+28% col = pow(clamp(col, 0.0, 1.0), vec3(1.0 / 1.85)); // Gamma 校正 finalAlpha = smoothstep(0.06, 0.92, finalAlpha);

360° Orbit & Sort

360° 轨道旋转与自由环绕由四层机制协同实现：1. 加载时计算 AABB 包围盒将几何质心归零至 (0,0,0)；2. 保持模型顶点静止，驱动相机沿球面极坐标方程环绕运动；3. C++ NDK 层每帧按当前视线方向执行深度基数排序；4. 顶点着色器在裁剪空间展开 Billboard 面片。

1. AABB 质心归零 + 球面极坐标轨道相机

计算包围盒中心 $\mathbf{c} = \frac{\mathbf{p}_{\min}+\mathbf{p}_{\max}}{2}$ 并归一化至 $[-1,1]^3$。每帧由偏航角 $\theta_{\text{yaw}}$ 与俯仰角 $\phi_{\text{pitch}} \in [-1.45, 1.45]$ 计算相机坐标 $\mathbf{E}$：

// 开启 360° 自动展台旋转 if (isAutoRotate) rotY += 0.008f eyeX = targetX + R * cos(rotX) * sin(rotY) eyeY = targetY + R * sin(rotX) eyeZ = targetZ + R * cos(rotX) * cos(rotY) Matrix.setLookAtM(viewMatrix, 0, eyeX, eyeY, eyeZ, targetX, targetY, targetZ, 0f, 1f, 0f)

相机视角更新时，按当前视线方向重排所有高斯椭球的混合顺序并正对屏幕展开：

// 1. Q1：在拍照采样阶段，传统 Mesh 摄影测量与 3DGS 辐射场采样有什么区别？

涉及模块：SpatialCaptureGuide.kt NativeProCameraController.kt
技术问答 Q&A
📌 A：核心解答
传统 Mesh 采样面向刚性几何三角化，假设表面满足各向同性漫反射，排斥移动高光，但支持后期 UV 匀光修补与局部特写拼接；3DGS 采样面向连续体积辐射场，利用球谐函数拟合随视角变化的高光，支持陶瓷与金属反光材质，但对自动曝光波动高度敏感，且要求完整覆盖上、中、下三层半球视角。
采样对比维度 传统 Mesh 摄影测量 (SfM + MVS + UV 贴图) 3D Gaussian Splatting (3DGS 辐射场采样) 本项目工程实现
1. 高光与反光材质 排斥高光：高光随视角移动会导致立体匹配失败与网格破洞 直接支持：利用球谐函数 (SH) 拟合随视角流动的高光，需多仰角采集光泽变化 内置高光模型支持；引导多仰角环绕采集
2. 自动曝光 (AE) 波动 中度敏感：后期 UV 贴图烘焙可通过 Multi-band Blending 匀光修补接缝 高度敏感：全图光度损失 ($L_1+\text{D-SSIM}$) 会把曝光明暗跳变拟合成空中悬浮噪点 (Floaters) NativeProCameraController 硬件级锁定 ISO、快门与白平衡
3. 空间视角覆盖策略 局部重叠拼接：相邻图重叠 >70%，支持近距离局部特写 全局视锥交叉约束：需完整环绕覆盖上、中、下三层半球视角 SpatialCaptureGuide 3 层俯仰角 × 12 扇区 = 36 单元穹顶雷达
4. 毛发与薄片边缘 泊松表面重建易将细微结构粘连或平滑滤除 依靠椭球拉伸与 $\alpha$ 渐变还原边缘细节，需补充切向掠射角采样 支持自由视角与连续视频流关键帧抽取 (VideoKeyframeExtractor)

Q2：为什么移动端本地秒级重建的模型偏稀疏，而离线训练的 3DGS 模型连续光滑？

涉及模块：PhotoReconstructor.kt SurfaceMesher.kt UniversalPlyLoader.kt
技术问答 Q&A
📌 A：核心解答
两者处于不同的计算层级：移动端本地重建在数秒内执行特征反投影与 SurfaceMesher 局部拓扑插值，用于无网环境下快速验证三维结构与采集完整度；离线 3DGS 训练在桌面级 GPU 上运行 COLMAP 后经历 30,000 轮反向传播迭代，对高斯球执行分裂、克隆与剪枝生成百万级椭球。本项目通过 UniversalPlyLoader 同时支持导入并 60 FPS 渲染离线训练的标准 PLY 模型。

1. 手机端本地秒级重建（3.5s ~ 7.5s）

  • 定位：端侧即时几何重建与现场采集校验。
  • 过程：CPU 协程并发提取 Sobel 边缘与表面采样点 $\rightarrow$ 圆弧针孔反投影 $\rightarrow$ SurfaceMesher 体素滤波与重心插值致密化。
  • 特点：无需云端 GPU 服务器、零网络开销、数秒内输出三维点云。

2. 桌面/云端 3DGS 完整训练（15 ~ 40 分钟）

  • 定位：高保真辐射场拟合（Inria 3DGS / Postshot / Nerfstudio）。
  • 过程：在独立显卡上执行 30,000 次可微光栅化与梯度反向传播，动态执行自适应密度控制（Splitting / Cloning / Pruning），生成 50 万~200 万个各向异性椭球。
  • 无缝衔接：通过 UniversalPlyLoader 支持直接导入并 60FPS 渲染标准 `.ply` 模型。

Q3：为什么标准 3DGS PLY 模型直接渲染会出现色彩暗淡发灰或半透明？如何还原？

涉及模块：GaussianRenderer.kt UniversalPlyLoader.kt
技术问答 Q&A
📌 A：核心解答
3DGS 模型需经过辐射度体积合成（Radiance Compositing）管线还原：1. 标准 PLY 中的 opacity 为 logit 值，需经 Sigmoid 激活函数还原物理不透明度；2. 球谐系数输出为物理线性光度，需在片元着色器中执行 Gamma 1.85 转换与 28% 饱和度补偿以适配 sRGB 屏幕；3. 3D 渲染视口采用独立深黑背景（#06101E）提升浅色模型边缘对比度。

1. 体积辐射累积合成

按从前向后体积累积公式 $C = \sum c_i \alpha_i \prod (1-\alpha_j)$ 逐层叠加，并对 `raw_opacity` 执行 Sigmoid 激活还原。

2. 线性空间转 sRGB Gamma

球谐颜色位于 Linear Space，片元着色器通过 pow(col, 1.0/1.85) 与 mix(gray, col, 1.28) 还原屏幕色彩。

3. 深色 3D 视口对比

3D 展示区域保持 #06101E 深色背景，使浅色与半透明边界清晰锐利。

Q4：拍照确认与端侧质检是如何从 0.8s~1.8s 优化至毫秒级（< 5ms）的？

涉及模块：MainActivity.kt ImageQualityEvaluator.kt TargetTrackerEngine.kt
技术问答 Q&A
📌 A：核心解答
早期延迟源于主线程全尺寸原图（12MP~48MP）解码旋转重压缩、单次拍照重复解码 3 次以及逐像素调用 Bitmap.getPixel() JNI 方法。优化后采用：1. ResolutionSelector(1280×960) 限制采集尺寸；2. Dispatchers.Default 后台协程单次 360px 下采样解码并在内存复用；3. Bitmap.getPixels() 批量读入 IntArray 配合单趟在线方差公式计算，将单帧质检耗时降至 5ms 以内。
优化维度 优化前实现（总耗时 800ms ~ 1800ms） 优化后原生实现（总耗时 < 30ms，质检 < 5ms）
1. 原图 EXIF 旋转处理 主线程同步解码 12MP~48MP 全尺寸原图、旋转矩阵并重压缩 JPEG 覆写磁盘（500~1500ms） 移除原图重压缩覆写，改在 Dispatchers.Default 后台协程执行内存级旋转
2. 磁盘 I/O 解码次数 单次拍照对同一文件连续调用 3 次 BitmapFactory.decodeFile 通过 decodeBitmapWithExif(file, maxSide=360) 仅执行 1 次下采样解码并内存复用
3. 像素遍历与方差算子 双层循环逐点调用 bitmap.getPixel(x,y) + MutableList<Float> 装箱 bitmap.getPixels() 一次性读入 IntArray，基于 $\text{Var}(X)=E[X^2]-(E[X])^2$ 单趟计算（< 5ms）
4. 采集分辨率与模式隔离 默认最高像素输出；未区分空间模式与单体模式 配置 ResolutionSelector(1280×960)；仅在 ScanMode.OBJECT 模式下启用主体偏离校验

Q7：移动端如何在有限内存与算力下实现十万级椭球的 60 FPS 渲染并避免 OOM？

涉及模块：UniversalPlyLoader.kt GaussianRenderer.kt NativeSplatBridge.kt
技术问答 Q&A
📌 A：核心解答
通过四层机制保障：1. 读取大型二进制 PLY 时使用 64KB BufferedInputStream 按自适应步长流式抽样；2. 顶点缓冲直接分配在 Native DirectByteBuffer，零拷贝上传至 OpenGL VBO；3. 景深排序在 C++ NDK 层使用基数排序完成，规避 JVM GC 停顿；4. Compose AndroidView.update 仅更新标量与 Uniform，仅在数据源变化时通过 LaunchedEffect 上传 VBO。

1. 内存控制：流式解析 + DirectBuffer

  • 流式读取：UniversalPlyLoader 支持 ASCII 与 binary_little_endian，仅实例化满足 i % sampleStep == 0 的顶点。
  • 零拷贝显存上传：ByteBuffer.allocateDirect(splatCount * 6 * 56) 直接对接 OpenGL VBO。

2. 帧率保障：C++ 基数排序 + 动态尺寸缩放

  • C++ NDK 排序：避免在每帧 16.6ms 渲染周期内触发 JVM 垃圾回收。
  • 视距自适应 Splat 半径：顶点着色器动态计算 dynamicSize = baseFactor / sqrt(zoom)。

Q8：如何实现无权限将 OpenGL 3D 画面保存至系统相册，以及导出标准 PLY 文件？

涉及模块：MediaStoreSaver.kt PlyExporter.kt GaussianRenderer.kt
技术问答 Q&A
📌 A：核心解答
遵循 Android 分区存储规范（Scoped Storage）：1. 保存相册时，在 GL 渲染线程帧末调用 glReadPixels 抓取显存 RGBA 缓冲，使用 postScale(1f, -1f) 翻转校正 OpenGL 左下角原点与 Android Bitmap 左上角原点的坐标差异，再通过 MediaStore 写入 Pictures/Remy3D；2. 导出 PLY 时，通过系统 SAF 框架（CreateDocument）流式输出标准 PLY 文件。
// GaussianRenderer.kt 帧末显存抓取与垂直镜像翻转 GLES20.glReadPixels(0, 0, w, h, GLES20.GL_RGBA, GLES20.GL_UNSIGNED_BYTE, pixelBuf) val rawBmp = Bitmap.createBitmap(w, h, Bitmap.Config.ARGB_8888) rawBmp.copyPixelsFromBuffer(pixelBuf.rewind()) // OpenGL 原点位于左下角，Android Bitmap 原点位于左上角，执行 Y 轴镜像翻转 val matrix = AndroidMatrix().apply { postScale(1f, -1f) } val flippedBmp = Bitmap.createBitmap(rawBmp, 0, 0, w, h, matrix, true) MediaStoreSaver.saveBitmapToGallery(context, flippedBmp)
